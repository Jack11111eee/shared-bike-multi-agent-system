## 3. 底图素材：小规模验证做了什么

1. **下载并裁剪**：GSHHG 149 MB 归档 → 厦门 62 KB / 上海 482 KB 提取；
   Geofabrik 上海 47 MB + 福建 93 MB → 同一份提取里的水系与行政界。
2. **渲染预览并目视核对**：把裁剪结果画成图，确认厦门岛、九龙江口、黄浦江、
   长江口的位置与格网相对关系正确（`docs/visual-evidence/` 下的底图核对图）。
3. **否决了三个候选**：Natural Earth 10m（厦门岛仅 30 点，轮廓失真）、
   Overpass 实时拉取（公共实例 502，且依赖在线服务）、OSM 全量 coastline-split
   （96 MB，需要额外切分）。理由见 `docs/basemap-sources.md` §2。
4. **许可核对**：两份归档内自带许可文本，已复制进 `replay/basemap/licenses/`。

## 4. 坐标证据：为什么不能"猜"

`REQUIREMENTS-PHASE5.md` §2.1 明确要求"坐标字段存在不等于坐标系已证明"。实际调查结果：

- **XM 有声明**：数据集 README 的 Metadata 表写明 WGS-84。这是 A 级证据，直接用。
- **SH 没有声明**：源 CSV 只有 `start_location_x/y`，上游仓库 README 也没写。
  于是改用**控制点量测**：以 OSM 道路中心线为参照，量 8,000 条订单起点的平均位移。
  原始坐标按 WGS-84 解释时平均位移 **7.1 m**；按 GCJ-02 解回 WGS-84 时 **20.0 m**；
  按 WGS-84 转 GCJ-02 时 **10.4 m**。若数据真是 GCJ-02，四个象限应一致地偏移
  (+436, −210) m 量级——实测四象限都在个位数到几十米，**该假设被排除**。
- **结论**：两源都按 WGS-84 直接叠加，**不做任何转换**。SH 的残余风险（某种未公开的
  局部加密）在 `docs/crs-evidence.md` §3.4 写明。

## 5. 导出工具与三处取舍

### 5.1 工具

| 工具 | 版本 | 用途 | 是否进入运行时依赖 |
|---|---|---|---|
| Google Chrome | 156.0.8078.79 | 打开页面、点击控件、截图 | 否 |
| websockets | 16.1.1 | 直连 CDP（不引入 Selenium/Playwright） | 否 |
| ffmpeg / ffprobe | 7.1.1 | 编码 WebM、验证可解码 | 否 |

`python3 scripts/capture_presentation.py --check` 会打印这三项的路径与版本；
缺任何一项都返回非零并给出准备步骤。

### 5.2 取舍一：底图用 GSHHG 而不是 Natural Earth

Natural Earth 10m 的厦门岛只有 30 个顶点，画出来是一个近似菱形，达不到
"足以辨认空间位置"的要求。GSHHG `h` 级在同尺度下足够，且许可明确允许分发。

### 5.3 取舍二：水系按可见长度筛选

上海窗口内有 1,238 条 river + 1,470 条 canal，全画出来会把黄浦江埋进网格。
按 ≥1.5 km 筛选后保留 535 条，主河道清晰、支流仍可辨。这是**选择规则**，
不是简化，记录在 `data/basemap/raw/manifest.json` 的 `selection` 字段。

### 5.4 取舍三：预测数据用 base64 而不是 JSON 数字

SH 有 37,995 个测试点 × 4 条浮点序列。JSON 十进制表示需要 3.71 MB，
`%.10g` 需要 1.27 MB 但**不再逐位等于 parquet**。改用 base64 小端 float64
（1.62 MB，逐位精确），加上整数 `actual` 保持可读，两源合计 1.80 MiB。
净流量不单独存储——页面从 out/in 相减得到，省下 0.9 MiB。
