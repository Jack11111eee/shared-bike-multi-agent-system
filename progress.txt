## Learnings / gotchas

- `order data.csv` and `STATION.csv` are actually XLSX files despite the extension.
- The feedback gate fingerprints every non-filtered output line, so `pytest -q`'s
  dots line counts as a "failure". The PRD feedback command was changed to
  `python3 -m pytest -q --tb=no -rf 2>&1 | grep -E "^(FAILED|ERROR)" || true`,
  which emits nothing on green and FAILED/ERROR lines on failure. The baseline was
  re-recorded after that change (the original baseline was recorded before any tests
  existed, so it only contained "no tests ran").
- The min-cost-flow planner must exclude deficit cells from the supply set; otherwise
  the solver "serves" a cell from itself with zero-distance flow and wastes the budget.

## Learnings / gotchas (Phase 2)

- `pandas` `.astype(int)` on the pivoted returns array truncates per cell; that is
  safe only because panel counts are integral. F8-2 checks the sum on every bucket,
  so a future fractional panel would fail loudly rather than silently.
- `file://` cannot `fetch()` sibling JSON (CORS), so the frame payload has to be
  inlined in each page. That is the reason for the 23 KB/page average, not a bug.
- An SVG `marker` without `markerUnits="userSpaceOnUse"` scales with `stroke-width`
  and produces arrowheads larger than the cells; both are needed to look right.
- The first version of the agent conclusion quoted a computed percentage and a
  summed total. F11-5 rejects those — every cited number must be copied verbatim
  from a tool response, so the planner now quotes only direct values.

## 第二轮：架构评审 REJECTED 后的修复（4 个阻塞缺陷）

评审结论是 REJECTED，理由是"四个门禁都不看 JS 渲染后的 DOM"。我逐条复现后确认成立：

**1（阻塞）差分图在真实浏览器里是空白。** `analysis_payload()` 不发布 `cell_px`/`cell_gap`，
而 `workbench.js` 用 `data.cell_px + data.cell_gap` 算坐标、用它设 `width`/`height`，
于是每帧 `renderGrids()` 把 Python 预渲染好的 rect 全删掉、重建出 169/255 个
`x="NaN" width="undefined"` 的零尺寸格子。实测（headless Chrome，file://）169 个 rect 的
`getBoundingClientRect().width` 全是 0，`browser_smoke.py` 的 `deltaCells` 只是 `querySelectorAll`
计数，照样是 169 —— 门禁全绿，页面全空。

修法不是补两个字段，而是**去掉第二个渲染器**：`renderGrids()` 改成原地更新预渲染的 rect
（`data-delta`、`fill-opacity`、`class`、`title`、`aria-label`、以及新增的 `text.delta-glyph` 的
`−`/`+`/空），不再 `createElementNS`。几何只由 Python 产出，`workbench.js` 里不再出现
`cell_px`/`cell_gap`（新增检查项与测试断言这一点）。顺带删掉 JS 给每个 rect 加的
`tabindex="0"` —— 那让 255 个格子变成 255 个 tab 停靠点，和 README 的说法自相矛盾。

**2（阻塞）证据链与屏幕数字不一致。** `data-join-key`/`data-operands` 由 Python 按 `frames[0]`
烤死，JS 只改 `data-value` 与文本。实测初始态：账本显示 `inventory_end = 163`，
而它自己的 `data-operands` 是 `{inventory_start:0, moved_in:200, ...}`（算出 0）；
`data-join-key` 写 `08:00` 而页面显示 `06:00`。
修法：`renderSummary`/`renderLedger` 每帧从同一份 state 重写 `data-join-key`，
派生值重写 `data-operands`（非派生值 `removeAttribute`），`#frame-label`/`#bucket-label` 的
关联键也随帧更新。

**3（阻塞）数据源切换是死控件。** XM 页只加载 `xm/presentation.js`，`PRESENTATION_DATA` 只有
`['xm']`，`core.sourceHref('sh')` 返回 `null`，点击无任何反应；而首页还写着"可随时切换"。
同时 `test_presentation_ledger.py` 的 node 夹具**同时加载两源**，测了一个线上页面不存在的行为。
修法：切换控件改成 `<a href="../sh/workbench.html">`（每源一页、各自加载自己的包；两包同页会
把 `replay/` 推过 8 MiB 上限），删掉那段永远走不到的 click 处理；测试改成只加载本页单源，
并断言"另一源的 bundle 未加载 → `sourceHref` 返回 null"，正是死控件的成因；首页文案改成
"每个数据源各有独立的工作台页，页首的 S-XM / S-SH 链接直接跳到另一源"。

**4（阻塞）`build_presentation` 的返回值不是契约里枚举的那份。** 缺 `evidence`，

`attach_guide()` —— "单次构建"实际是两步。修法：`build_presentation` 现在自己返回

## 修复：浏览器冒烟不再写进已发布站点（根因，而非再清一次残留）

`check_presentation --phase 4` 反复报 `stray_files: ['xm/workbench.smoke.html']`。根因不是"清理不干净"，
而是冒烟脚本把注入后的页面**写进了 `replay/<source>/`**，好让相对引用能被解析；于是：

- 一次被强杀的冒烟会把页面留在站点里；
- 两个校验进程同时跑时，一个会看到另一个的临时页面，误判为 stray 文件；
- 基线重录恰好撞上这种并发，把 `phase 4: 1 of 38 checks FAILED` 记进了基线，之后"全绿"反而成了新签名。

修法（`scripts/browser_smoke.py`）：冒烟页改写进 `tempfile.TemporaryDirectory()`，并把页面里所有相对
`src`/`href` 重写成绝对 `file://` URI（`_absolute_refs`）——仍然离线、仍是同一份字节，但**已发布站点
不再被测试写入**。旧版本可能留在树里的页面仍在启动时清掉。验证：`browser_smoke.py` 对 xm/sh 各
20 步无错误，运行前后 `replay/` 里 `*.smoke.html` 计数都是 0。

这条改动只影响开发用冒烟脚本，不碰站点内容、不碰断言强度（NF-24 仍然把任何多余文件判为 stray）。
